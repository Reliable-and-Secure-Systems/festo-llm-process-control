# Exp4 — Predictive Look-Ahead (SP + CoT + P)

## Overview

Exp4 corresponds to **Row 4 in Table I** and evaluates predictive look-ahead with the **SP + CoT + P** prompting strategy.

The experiment uses a fine-tuned Llama 3.2 3B model, a 6-step process history, and a **3-step predictive horizon**.

**Experiment strategy: SP + CoT + P**

- **SP:** System Prompt
- **CoT:** Chain-of-Thought
- **P:** 3-step predictive look-ahead
- **FS:** Not used

Exp4 uses **3,000 training records** and **250 live closed-loop evaluation decisions**.

---

## 1. System

The controlled system is a simulated Festo MPS PA dual-tank process.

| Variable | Target | Acceptable Range |
|---|---:|---:|
| Upper tank level | 45% | 40–50% |
| Water temperature | 35°C | 32–38°C |

The controller operates at a **5-second decision interval** and maintains a **6-step history window**.

### Hardware Safety Limits

The LLM is subject to three hardware safety constraints:

1. Temperature > 38°C → heater OFF
2. Level > 70% → pump OFF and valve OPEN
3. Pump + valve simultaneously → pump OFF

These are applied externally after the LLM generates its action.

Exp4 uses:

**3,000 training records**

The training dataset is used for fine-tuning the Llama 3.2 3B model.

The live closed-loop evaluation is separate:

| Data | Count |
|---|---:|
| Training records | 3,000 |
| Live evaluation decisions | 250 |

## 3. Prompting Strategy

Exp4 uses exactly:

```text
SP + CoT + P
````

The corresponding implementation is:

```text
PROMPT_VARIANT=v3_cot
```

### SP — System Prompt

The system prompt defines:

* Controller role
* Required JSON output
* Actuator fields
* Level and temperature targets
* Valid value types
* Predictive-horizon requirement

### CoT — Chain-of-Thought

The controller is instructed to reason through:

1. Level error
2. Temperature error
3. Predicted future states for both variables
4. Final control action

### P — Predictive Look-Ahead

A **3-step future horizon** is provided to the model so that it can assess whether the selected action is expected to move both variables toward their targets.

### Few-Shot

**Few-shot examples are not used in Exp4.**

Therefore:

```text
Exp4 = SP + CoT + P
     = v3_cot
```

---

## 4. Predictive Look-Ahead

The prediction horizon is:

```text
3 steps
```

For each decision, the supervisor computes:

```text
t+1: level=...%, temp=...C
t+2: level=...%, temp=...C
t+3: level=...%, temp=...C
```

The nominal prediction model uses:

| Parameter                   |   Value |
| --------------------------- | ------: |
| Prediction horizon          | 3 steps |
| Fill rate                   |    3.27 |
| Drain rate                  |    1.58 |
| Heat rate                   |   0.074 |
| Cool rate                   |  0.0173 |
| Thermal inertia             |       3 |
| Inertia factor              |     0.3 |
| Float cutoff                |     47% |
| Temperature hysteresis low  |    34°C |
| Temperature hysteresis high |    36°C |

The prediction is generated by simulating the nominal action forward for three steps.

Base model:

meta-llama/Llama-3.2-3B-Instruct

The base model is loaded using:

# Reproduction Procedure

## 6. Environment Setup

Use a CUDA-capable Python environment with the required:

* PyTorch
* Transformers
* PEFT
* BitsAndBytes

Hugging Face access is required for the base model.

Create a local `.env` file containing:

```text
HUGGING_FACE_KEY=<your-token>
```

**Do not commit `.env` to GitHub.**

---

## 7. Ensure the Fine-Tuned Model Is Available

Place the Exp4 fine-tuned adapter and checkpoints in the experiment's model directory.

The supervisor automatically searches for `checkpoint-*` directories and selects the latest checkpoint.

---

## 8. Start the Festo Simulator

Start the simulator:

```bash
./simulated_festo
```

Keep the simulator running.

The simulator provides the live process state used by the LLM controller.

---

## 9. Run Exp4

Exp4 must use:

```text
PROMPT_VARIANT=v3_cot
```

Run:

```bash
PROMPT_VARIANT=v3_cot python -u llm_supervisor_exp07.py
```

This selects:

```text
SP + CoT + P
```

and does **not** include few-shot examples.

The supervisor confirms the selected variant at startup.

---

## 10. Closed-Loop Control

For each control cycle, the supervisor:

1. Reads the live sensor state.
2. Maintains the latest 6-step history.
3. Computes the 3-step predictive horizon.
4. Builds the SP + CoT + P prompt.
5. Generates the LLM control action.
6. Parses the JSON response.
7. Checks the generated action.
8. Applies the hardware-safety layer.
9. Writes the actuator command.
10. Records the decision and metrics.
11. Waits 5 seconds before the next cycle.

The experiment terminates automatically after:

**250 decisions.**
